## Новые интеграционные проверки

Использована временная SQLite-база с настоящими миграциями, Prisma и API. Рабочие данные не используются.

- Все 12 сочетаний 4 способов связи × 3 способов доставки для гостевых заказов.
- Телефон, Telegram, WhatsApp, email для авторизованного checkout; серверная корзина, комментарий и скидка 1000 → 850 ₽.
- Сохранение contactMethod, contactDetails, deliveryMethod, многострочного comment в Order и доступность в административном API/собственных заказах.
- Нормализация Telegram ссылок в @username; отсутствие устаревшего Telegram-контакта при выборе другого канала.
- Email обязателен при выборе связи по почте; у авторизованного пользователя возможен fallback на email профиля.
- Неизвестные/нестроковые способы доставки и связи, пустой/неверный email, пустой/неверный Telegram, противоречивое isPickup/deliveryMethod и отсутствие адреса доставки дают ошибку без создания заказа и списания товара.
- Комментарий необязателен, многострочный, до 2000 символов; более длинный и нестроковый отклоняется.
- Совместимость старого isPickup с самовывозом, правильный адрес магазина.
- HTML-шаблон уведомления содержит доставку/связь/комментарий; HTML из комментария экранируется; adminNote отсутствует.
- Миграция сохраняет прежние комментарии, приватные заметки, суммы, связи и поисковый индекс; исторический самовывоз определяется по прежнему адресу, старым доставкам не назначается неизвестный перевозчик.

## Браузерные проверки новых полей

Chromium, локальный production Next (`next start`, порт 3107), отдельная временная SQLite-база:

- гостевой заказ СДЭК + Telegram + многострочный комментарий;
- гостевой заказ Почта России + email + комментарий;
- гостевой самовывоз + WhatsApp + комментарий;
- выбранные поля отображаются на подтверждении, сохраняются в базе и показываются в карточке административного заказа;
- авторизованный заказ СДЭК + телефон + комментарий отображается в личном кабинете;
- пустые email/Telegram блокируют переход к подтверждению с понятной ошибкой;
- при переключении доставка → самовывоз → доставка ранее введённый адрес сохраняется.

## Регрессия

Пройдены прежние сценарии гостевой localStorage-корзины, оформления без регистрации, промокодов/минимума/периода/лимитов, серверных цен и скидок, параллельных заказов, отката транзакции, личного кабинета, административного управления промокодами, добавления/редактирования/очистки приватных заметок и их недоступности покупателям.

## Границы проверки

- Настоящий SMTP не подключён: в логах есть ECONNREFUSED для уведомлений о заказе. Формирование шаблона проверено отдельно, реальная доставка email не подтверждена.
- Telegram/WhatsApp — предпочтения для менеджера, без автоматической отправки сообщения. API и реальные тарифы СДЭК/Почты России не подключались: этот релиз добавляет выбор перевозчика, не расчёт доставки.
- Git push, серверная миграция и PM2 здесь не выполнялись. После вашего push примените включённую миграцию через скрипт развёртывания с резервной копией БД.
