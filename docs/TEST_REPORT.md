## Интеграционные тесты — 20/20 PASS

`npm run test:checkout`: временная SQLite-база, настоящие миграции, сервис Prisma и обработчики API. Рабочая база не использовалась.

Проверены:
- гостевой заказ без регистрации, email и создания User;
- промокод 15%: subtotal 1000, discount 150, total 850, сохранение всех значений в Order;
- игнорирование переданных клиентом price/total/discount/userId;
- серверная корзина авторизованного покупателя, фиксированная скидка 150 ₽, очистка корзины и доступ к собственному заказу;
- неверный, просроченный, выключенный, ещё не действующий промокод, минимальная сумма и исчерпанный лимит;
- лимит 1: второй заказ отклоняется;
- четыре параллельных заказа с одним оставшимся применением промокода: создан ровно один заказ;
- два параллельных заказа на последний товар: создан ровно один заказ, остаток не отрицательный;
- принудительная ошибка вставки OrderItem после резервирования: Order, склад и usedCount полностью откатываются;
- объединение дубликатов позиций, суммарный остаток обычных товаров + упаковок;
- отрицательное, нулевое, дробное и слишком большое количество, поддельная упаковка, обязательные поля и email;
- самовывоз без адреса, ограничение фиксированной скидки суммой заказа;
- создание/отключение промокода администратором, запрет изменения usedCount, отображение данных гостевого заказа и изменение его статуса;
- дубликаты кодов, процент >100 и обратный период действия;
- отсутствие доступа гостя к списку заказов; плохой/пустой Authorization не считается гостевой сессией;
- некорректные тела запросов;
- применение новой миграции к прежней схеме с тестовыми данными: старый Order, OrderItem, Message, итог и скидка сохранены, subtotal/email восстановлены, foreign_key_check пуст, поисковая таблица product_fts осталась.

## Браузерные тесты — 7/7 PASS

`npm run test:e2e` с системным Chromium через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Проверен именно локальный production Next (`next start`, порт 3107), отдельная временная SQLite-база. Финальный прогон: 24.0 секунды.

1. Товар → гостевая localStorage-корзина → перезагрузка → checkout → доставка → заказ. ID показан; регистрация предлагается только после успеха; User не создаётся; корзина очищается.
2. Гостевой checkout с 15% и самовывозом: в UI 850 ₽, в SQLite subtotal 1000, discount 150, total 850, код сохранён.
3. Изменение количества гостевой корзины, применение скидки, пересчёт суммы и удаление позиции.
4. Авторизованная серверная корзина, промокод, заказ и его отображение в существующем личном кабинете.
5. Неверный/просроченный код: понятная ошибка, скидка снимается.
6. Исчерпанный лимит: повторное оформление и применение отклоняются.
7. Настоящий вход в админку, Настройки → Промокоды, создание и отключение кода; отображение промокода/скидки в административных заказах.

## Ограничения проверки

- SMTP в тестовой среде отсутствует: в логах есть ECONNREFUSED. Реальная доставка email не подтверждена. Это не блокировало и не откатывало созданные заказы; для гостя без email письмо клиенту не отправляется.
- Git push, серверная команда и `pm2 restart tophitt` здесь не выполнялись. Скрипт включён в архив, миграции и сборка проверены локально. На вашем сервере нужно проверить путь к проекту, версию Node, `.env`, DATABASE_URL, PM2 и права доступа.
- Конкурентные сценарии проверены на SQLite в тестовом процессе; промышленный нагрузочный тест нескольких серверов не выполнялся.
- Полный аудит безопасности, платёжная интеграция и проверка сторонних SMTP/служб не входили в эти тесты.
