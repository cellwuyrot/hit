# Гостевой checkout и промокоды

## Что изменено

- Гостевая корзина: `localStorage.guestCart`, только `productId`, `quantity`, `isPack`. Цены, скидки и итог берутся из Prisma через `/api/checkout/quote`.
- Авторизованный покупатель использует прежнюю серверную `CartItem`; переданные клиентом гостевые позиции игнорируются. Корзины не смешиваются автоматически.
- `/api/user/orders` POST принимает гостевой заказ без токена. GET по-прежнему требует авторизации и возвращает только собственные заказы. Некорректный токен не превращается в гостевой запрос.
- Имя и телефон обязательны; доставка требует адрес, самовывоз — нет. Email необязателен. Пользователь для гостевого заказа не создаётся.
- После заказа показан полный ID; гостю предлагается необязательная регистрация. Регистрация после заказа не привязывает старый гостевой заказ к аккаунту автоматически.
- `src/lib/checkout.ts` — общий транзакционный сервис расчёта и оформления, используемый обоими checkout, проверкой промокодов и предпросмотром суммы. Проверяет количество, настоящую упаковку, суммарный остаток обычных/упаковочных позиций, цену и правила промокода. Сохраняет прежнюю скидку 10% за упаковку и округление до рубля; процентная скидка также округляется до рубля, денежные итоги — до копейки.
- В заказе сохраняются `subtotal`, `discount`, `total`, `promoCode`, email для уведомлений; `userId` nullable. Стоимость единицы в OrderItem сохраняется как сумма позиции / количество, включая упаковочную скидку.
- Остатки, промокод, счётчик использований, создание заказа и очистка серверной корзины находятся в одной транзакции. При ошибке всё откатывается. SMTP работает после коммита и не влияет на создание заказа.
- Админка → Настройки → Промокоды: создание, редактирование, тип и величина скидки, минимум, начало/окончание, включение/отключение, лимит и счётчик. Лимит 0 — без ограничений; пустые даты — без ограничения. Даты формы вводятся в локальном времени браузера, сервер получает UTC. Счётчик не редактируется клиентом.
- Административные заказы поддерживают гостя и показывают код, скидку и итог. Старые заказы сохраняются миграцией; subtotal/email восстанавливаются из прежних данных.
- Исправлены исходные ошибки lint без отключения правил. Предупреждения о старых `<img>` и других существующих компонентах не блокируют lint.

## Две команды для обновления

Распакуйте архив **поверх рабочей копии репозитория на ПК**, сохраняя `.git`, `.env`, реальную БД и `public/uploads`. В архиве нет этих локальных данных.

**1. ПК — Git Bash, из каталога вашего репозитория:**

```bash
git add . && git commit -m "Add guest checkout and transactional promo codes" && git push
```

**2. Сервер — замените путь на каталог проекта:**

```bash
cd /path/to/tophitt && git pull --ff-only && bash scripts/deploy-pm2.sh
```

Используется текущая ветка и её настроенный upstream — имя ветки не предполагается. Скрипт выполняет npm ci --include=dev, Prisma validate/generate, lint/build, останавливает `tophitt`, делает SQLite backup, применяет `prisma migrate deploy`, перезапускает PM2 с `--update-env` и сохраняет список процессов. Имя процесса можно переопределить переменной `PM2_APP_NAME`.

Обязательные условия: Node.js 20.19+ / 22.12+ / актуальный 24 (Next/Prisma), npm, PM2, настроенный git upstream, доступ на запись, корректная серверная `.env` с `JWT_SECRET` и `DATABASE_URL`. `DATABASE_URL` должен указывать на существующую SQLite-базу проекта. Prisma и низкоуровневый SQLite теперь используют этот же путь; по умолчанию runtime использует `dev.db` в корне. Не подменяйте рабочую БД тестовой и не запускайте seed на production.

При ошибке validate/lint/build процесс не останавливается. При ошибке backup/миграции процесс остаётся остановленным: сначала изучите ошибку и резервную копию в `backups/`, не запускайте новый код на несовместимой схеме. Не используйте `prisma migrate dev` или `db push` на production. До обновления рекомендуется внешняя копия проекта/БД и план отката; восстановление DB требует согласованного возврата к предыдущему коду.

## Проверки

```bash
npx prisma validate
npx prisma generate
npm run lint
npm run build
npm run test:checkout
```

`test:checkout` создаёт временную БД, применяет настоящие миграции и удаляет её после тестов; рабочая база не используется.

Для браузерных тестов (после build):

```bash
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты создают отдельную временную БД и запускают production Next на порту 3107. Можно использовать установленный Chromium через `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium`. Нужны свободный порт и системные библиотеки браузера. Отчёт конкретного выполненного прогона — `docs/TEST_REPORT.md`.
