# API и локальный агент новостей

## Как работает

1. `GET /api/agent/news/candidate?kind=random` выбирает случайный товар из наличия или группу товаров одного бренда. При выборе учитывается история последних 40 новостей агента; если неповторившихся позиций не осталось, выбор продолжается по всему каталогу.
2. Локальный агент передаёт ограниченные факты товара локальной OpenAI-совместимой модели и получает JSON по правилам из `docs/NEWS_ARTICLE_TEMPLATE.md`.
3. `POST /api/agent/news` повторно проверяет товары и сохраняет новость. Разметку создаёт сервер, а не модель; текстовые поля экранируются.
4. По умолчанию создаётся **черновик**. Публичная публикация требует явного `--publish` у скрипта и серверного `NEWS_AGENT_ALLOW_PUBLISH=true`.

Для API нужен `NEWS_AGENT_API_KEY` длиной не менее 32 символов. Передавайте его только в заголовке `Authorization: Bearer …`; ключ не передаётся через URL и не должен попадать в Git, браузер или логи.

## Настройка

1. Создайте секрет, например `openssl rand -hex 32`.
2. Добавьте `NEWS_AGENT_API_KEY=<секрет>` в серверный `.env` и перезапустите приложение.
3. На компьютере локального агента задайте:

```dotenv
NEWS_AGENT_API_URL=https://tophitt.ru
NEWS_AGENT_API_KEY=<тот же секрет>
NEWS_AGENT_LLM_URL=http://127.0.0.1:1234/v1/chat/completions
NEWS_AGENT_MODEL=<имя вашей локальной модели>
# Необязательно, только если ваш локальный сервер требует ключ:
NEWS_AGENT_LLM_API_KEY=
```

4. В проекте установите зависимости и выполните миграции по принятому процессу развёртывания:

```sh
npm ci
npx prisma migrate deploy
```

5. Запустите проверку без сохранения, затем создайте черновик:

```sh
npm run news:agent -- --dry-run
npm run news:agent
```

Чтобы агент публиковал сам, отдельно установите `NEWS_AGENT_ALLOW_PUBLISH=true` на сервере и запускайте его с `--publish`. Без обоих условий API не публикует.

## Эндпоинты

### Получить случайный кандидат

`GET /api/agent/news/candidate?kind=random`

`kind`: `random`, `product` или `brand`. Ответ содержит `kind`, `brand`, `productCount` и до пяти товаров с `id`, `name`, `brand`, `description`, `productType`, `tags`, `category`, `image` и внутренней ссылкой `url`.

### Создать новость

`POST /api/agent/news`, заголовки `Authorization: Bearer …` и `Content-Type: application/json`:

```json
{
  "productIds": ["ID_ТОВАРА_ИЗ_КАНДИДАТА"],
  "title": "Короткий новостной заголовок о товаре",
  "excerpt": "Краткое описание новости для карточки.",
  "lead": "Вступительный абзац с темой и проверяемым контекстом.",
  "sections": [
    { "heading": "Что есть в каталоге", "text": "Подтверждённые сведения о названии, бренде и категории выбранного товара из карточки каталога." },
    { "heading": "Как выбрать", "text": "Нейтральный практический контекст выбора без добавления свойств, которых нет в описании каталога." }
  ],
  "publish": false
}
```

`productIds` должны быть взяты из ответа API и всё ещё иметь остаток. Поля статьи валидируются по длине и количеству разделов. API формирует HTML из безопасного шаблона и добавляет ссылки только на карточки выбранных товаров.
