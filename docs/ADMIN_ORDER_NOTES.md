# Внутренние заметки администратора к заказам

## Использование

Админка → Заказы → нужный заказ → «Заметка администратора».

1. Нажмите «Добавить заметку», введите текст и нажмите «Сохранить заметку».
2. Для изменения нажмите «Редактировать заметку». «Отмена» не сохраняет изменения.
3. Для удаления очистите поле и сохраните.

Заметка хранится в базе, не исчезает при перезагрузке или изменении статуса/трек-номера. Разрешён многострочный текст до 5000 символов. Текст отображается как обычный текст, не как HTML.

Это отдельная внутренняя пометка для администраторов проекта, не комментарий покупателя и не сообщение в чате. Покупатель не видит заметку ни в личном кабинете, ни в JSON ответа API своих заказов; сохранение заметки не отправляет письмо. Все администраторы с доступом к заказам могут читать и редактировать общую заметку заказа. История версий и отдельные личные заметки для каждого администратора не добавлялись.

## Изменения

- `Order.adminNote String @default("")`.
- Добавочная миграция `20261001160000_order_admin_note`: ALTER TABLE, без пересоздания заказов или удаления данных. У старых заказов заметка пустая.
- Административный `PUT /api/admin/orders` сохраняет `adminNote` только по администраторскому токену, валидирует тип и длину; пустая строка очищает заметку.
- `GET /api/user/orders` исключает поле на стороне Prisma (`omit`), а не только в интерфейсе.
- Checkout не принимает `adminNote` от покупателя; внутреннее поле нельзя установить через создание гостевого/авторизованного заказа.
- Компонент `AdminOrderNote` в разделе «Заказы»: чтение, редактирование, сохранение, отмена, очистка, сообщения об ошибке.

## Установка обновления

Архив содержит весь проект с предыдущими гостевым checkout и промокодами. Распакуйте его поверх рабочей копии репозитория на ПК, сохраняя `.git`, `.env`, существующую БД и uploads. Затем сделайте commit/push в ветку с проектом.

На сервере из предыдущего обсуждения удалённый репозиторий называется `old-origin`, а изменения предполагаются в `main`. Если это по-прежнему так:

```bash
cd /var/www/tophitstore && git pull --ff-only old-origin main && bash scripts/deploy-pm2.sh
```

Явное указание `old-origin main` не зависит от прежнего некорректного upstream `release`. Если Git сообщает о локальных изменениях/расходящихся ветках — остановитесь и разберитесь, не применяйте reset --hard.

Скрипт собирает проект, делает резервную SQLite-копию в `backups/`, применяет миграции и перезапускает PM2 `tophitt`. Полная инструкция и условия — `docs/GUEST_CHECKOUT_DEPLOY.md`. Не используйте `db push` или `migrate dev` на рабочем сервере.

Результаты проверки новой версии — `docs/TEST_REPORT.md`.
