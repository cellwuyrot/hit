# Комментарий, предпочтительный способ связи и доставка

## Что доступно покупателю

Checkout → «Данные для доставки»:

- «Комментарий к заказу» — необязательный многострочный текст, до 2000 символов. Он показывается перед подтверждением и сохраняется в заказе, отдельно от приватной заметки администратора.
- «Предпочитаемый способ связи»: Телефон, Telegram, WhatsApp, Почта (email).
- Для Telegram появляется обязательное поле username/ссылка (`@username`, `https://t.me/username`, `t.me/username`). Username проверяется (5–32 символа), в заказе хранится `@username`.
- Для связи по почте email обязателен. При другом способе связи email по-прежнему необязателен; для авторизованного покупателя используется email профиля, если отдельный email не введён.
- WhatsApp использует указанный телефон. Имя и телефон остаются обязательными при любом способе связи.
- «Выбор доставки»: СДЭК, Почта России, Самовывоз.
- Для СДЭК/Почты России нужен полный адрес доставки или адрес пункта получения. Для самовывоза адрес покупателя не требуется: сохраняется адрес существующего склада магазина.
- При переключении доставки введённый адрес не стирается.

Способ связи — предпочтение для менеджера, не автоматическая отправка сообщения в Telegram/WhatsApp. Выбор перевозчика не подключает API СДЭК/Почты России и не рассчитывает тариф: стоимость и условия доставки уточнит менеджер. Текущий итог checkout относится к товарам и скидкам, не включает тариф перевозчика.

## Где видны данные

Комментарий покупателя, доставка и предпочтительный канал связи видны в административных заказах и в собственных заказах личного кабинета. Данные включены в существующие шаблоны уведомлений о заказе; пользовательский текст экранируется при формировании HTML-письма.

Приватная `adminNote` сохраняется как раньше и не попадает в ответы покупателю, в его кабинет или шаблон письма.

## Технические изменения

- `Order.contactMethod` (`phone`, `telegram`, `whatsapp`, `email`).
- `Order.contactDetails` — нормализованный Telegram username; для остальных способов пустая строка. Телефон/email берутся из отдельных полей заказа.
- `Order.deliveryMethod` (`cdek`, `russian_post`, `pickup`).
- Общее описание опций, подписей и валидации — `src/lib/order-options.ts`. Оно используется интерфейсом и транзакционным серверным сервисом оформления.
- Неизвестные способы и противоречивое сочетание `deliveryMethod`/старого `isPickup` отклоняются. Клиент не может произвольно записать способ доставки/связи или приватную заметку.
- Новая добавочная миграция `20261002150000_order_contact_delivery`: существующие заказы не пересоздаются. Исторические самовывозы по адресу помечаются `pickup`; прежним доставкам не назначается выдуманный перевозчик — в интерфейсе «Не указан (старый заказ)».
- Совместимость со старым API: без новых полей способ связи — телефон, а `isPickup: true` означает самовывоз. Старый запрос доставки без явного перевозчика трактуется как СДЭК; новый checkout отправляет явный выбор.

## Обновление

Полный архив включает предыдущие гостевые заказы, промокоды и внутренние заметки. Распакуйте его поверх репозитория на ПК, сохраняя `.git`, `.env`, рабочую БД и uploads. Сделайте commit/push обновления в `main`.

На вашем сервере (при прежнем remote `old-origin` и ветке `main`), одной строкой:

```bash
cd /var/www/tophitstore && git pull --ff-only old-origin main && NODE_OPTIONS="--max-old-space-size=4096" bash scripts/deploy-pm2.sh
```

Скрипт выполнит установку, Prisma validate/generate, lint/build, остановит PM2 `tophitt`, создаст согласованную SQLite-копию в `backups/`, применит `migrate deploy` и перезапустит PM2. Если миграция/backup не удались, процесс остаётся остановленным. Не удаляйте SQLite WAL/SHM-файлы и не применяйте `reset --hard` при ошибках Git.

Если SQLite всё ещё заблокирована после остановки `tophitt`, проверьте другие процессы/параллельные миграции. Полные условия развёртывания — `docs/GUEST_CHECKOUT_DEPLOY.md`; сервер не обновлялся автоматически в рамках этой работы.

Тесты и ограничения проверки — `docs/TEST_REPORT.md`.
