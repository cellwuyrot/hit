## Новая функция: что реально проверено

Интеграционные проверки используют временную SQLite-базу, настоящие миграции, Prisma и обработчики API:

- новый заказ имеет пустую adminNote;
- администратор сохраняет, редактирует и очищает многострочную заметку;
- заметка читается в административном списке и сохраняется в базе;
- комментарий покупателя, сумма, статус и трек не изменяются при сохранении заметки;
- изменение статуса/трека не стирает заметку;
- гость, покупатель и некорректный токен не могут читать/редактировать заметки через административный API;
- API собственных заказов покупателя не возвращает поле adminNote и его содержимое;
- нельзя передать внутреннюю заметку при создании гостевого или авторизованного заказа;
- допустим текст длиной 5000 символов; null, объект, число и 5001 символ отклоняются;
- несуществующий заказ даёт 404, неправильное тело запроса — 400;
- новая добавочная миграция сохраняет старые заказы, суммы, связи и поисковый индекс; у существующих заказов adminNote пустая.

В Chromium на production Next (`next start`, порт 3107), с отдельной временной базой, проверены:

- настоящий вход администратора;
- добавление заметки в разделе «Заказы»;
- сохранение после перезагрузки;
- редактирование, отмена несохранённых изменений и удаление заметки;
- отсутствие заметки в личном кабинете покупателя и JSON ответа API;
- запрет изменения заметки по пользовательскому токену.

Все прежние сценарии также прошли: гостевая localStorage-корзина, доставка и самовывоз без регистрации, серверная корзина авторизованного покупателя, личный кабинет, скидка 1000 → 850 ₽, фиксированная/процентная скидка, неверные/просроченные/выключенные/будущие промокоды, минимум суммы, лимит использований, административное создание/отключение промокода, защита от подмены цен/сумм/скидок, параллельные заказы на последний остаток/последнее применение промокода, откат транзакции при искусственном сбое, валидация количества и упаковок.

## Ограничения

- SMTP в среде проверки отсутствует: ECONNREFUSED в логах касается уведомлений о создании заказов предыдущего функционала. Доставка писем на настоящем сервере не проверена. Сохранение внутренней заметки не запускает отправку письма.
- Git push, обновление сервера и PM2 здесь не выполнялись. Нужны корректный DATABASE_URL, серверная .env, резервная копия и применение миграции. Скрипт обновления включён в архив.
- Заметка общая для администраторов с доступом к заказам; история версий/личные заметки по каждому администратору не добавлялись.
